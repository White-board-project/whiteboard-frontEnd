# 초기 페이지 기능 문서

초기 페이지는 사용자가 서비스에 처음 진입했을 때 워크스페이스를 **새로 만들거나**, 초대 코드로 **기존 워크스페이스에 참여**하도록 안내하는 프로젝트 진입 화면입니다.

이 문서는 PRD의 `9.1 초기 페이지` 요구사항과 Figma 화면 `17:595`, `17:549`를 기준으로 향후 구현 범위와 검증 항목을 정리합니다.

## PRD 매핑

### 핵심 사용자 시나리오


| PRD 시나리오          | 초기 페이지에서 담당하는 단계                                    | 이후 단계                                         |
| ----------------- | --------------------------------------------------- | --------------------------------------------- |
| 시나리오 1. 워크스페이스 생성 | 서비스 첫 화면 진입 → 워크스페이스 이름과 이메일 입력 → 생성 인증 링크 발송 요청    | 사용자가 이메일 링크를 클릭하면 워크스페이스를 생성하고 워크스페이스 페이지로 이동 |
| 시나리오 2. 워크스페이스 참여 | 초대 URL 또는 초대 코드 확보 → 초대 코드와 이메일 입력 → 참여 인증 링크 발송 요청 | 사용자가 이메일 링크를 클릭하면 기존 워크스페이스에 자동 참여            |


### 기능 요구사항 `9.1 초기 페이지`


| PRD 항목                  | 문서화된 구현 요구사항                                                  |
| ----------------------- | ------------------------------------------------------------- |
| 워크스페이스 생성               | 생성 카드에서 워크스페이스 이름과 이메일을 입력받고 생성 인증 링크 발송을 요청한다.               |
| 워크스페이스 참여               | 참여 카드에서 초대 코드와 이메일을 입력받고 참여 인증 링크 발송을 요청한다.                   |
| 사용자당 워크스페이스 최대 3개 생성 가능 | 생성 요청 실패 또는 제한 초과 응답을 사용자에게 명확히 표시한다. 정확한 API 응답 형식은 아직 미정이다. |
| 이메일 입력 UI 제공            | 두 플로우 모두 이메일 입력 필드를 제공한다.                                     |
| 인증 링크 발송                | submit 성공 후 이메일 인증 대기 화면으로 전환한다.                              |
| 링크 인증 후 생성 처리           | 인증 링크 callback에서 워크스페이스 생성 완료 후 워크스페이스 페이지로 이동한다.             |
| 초대 링크 기반 참여 처리          | 초대 링크 또는 초대 코드 기반 callback에서 워크스페이스 참여 완료 후 워크스페이스 페이지로 이동한다. |


## 화면 플로우 매핑

```text
/workspace-access 초기 진입 페이지
  ├─ 새 워크스페이스 만들기 제출
  │   └─ 이메일 인증 대기 화면
  │       └─ 생성 인증 링크 클릭
  │           └─ 워크스페이스 생성 후 워크스페이스 페이지 이동
  └─ 초대 코드로 참여하기 제출
      └─ 이메일 인증 대기 화면
          └─ 참여 인증 링크 클릭
              └─ 워크스페이스 자동 참여 후 워크스페이스 페이지 이동
```

## 기능 요구사항

### 입력과 검증


| 플로우       | 필드        | 필수 여부 | 검증 기준                                     |

## 구현 체크리스트

### 화면 구성

- `/workspace-access` 페이지를 Figma `17:595` 기준의 초기 진입 화면으로 구현하고 `/`에서 해당 페이지로 이동한다.
- 브랜드 앵커와 서비스명 `화이트보드`를 표시한다.
- 워크스페이스 생성 카드를 구현한다.
- 초대 코드 참여 카드를 구현한다.
- 매직 링크 안내 배지를 구현한다.
- 푸터 링크 영역을 구현한다.
- 발송 성공 후 Figma `17:549` 기준의 이메일 인증 대기 화면을 표시한다.
- 인증 메일 재전송 버튼과 성공 토스트를 구현한다.

### 폼과 API

- 생성 폼 schema를 정의한다.
- 참여 폼 schema를 정의한다.
- 생성 인증 링크 발송 API 함수를 정의한다.
- 참여 인증 링크 발송 API 함수를 정의한다.
- 인증 메일 재전송 API 함수를 정의한다.
- 각 submit을 TanStack Query mutation으로 연결한다.
- submit 중 중복 요청을 막는다.
- API 에러를 공통 에러 처리 정책에 맞춰 표시한다.
- 사용자당 워크스페이스 최대 3개 제한 응답을 별도 메시지로 처리한다.

### 인증 링크 처리

- 생성 인증 callback 라우트를 확정한다.
- 참여 인증 callback 라우트를 확정한다.
- 생성 callback 성공 시 워크스페이스 페이지로 이동한다.
- 참여 callback 성공 시 대상 워크스페이스 페이지로 이동한다.
- callback 실패 시 재시도 또는 고객 지원 경로를 안내한다.

### 테스트

- 생성 카드 렌더링 테스트를 작성한다.
- 참여 카드 렌더링 테스트를 작성한다.
- 필수 입력값 검증 테스트를 작성한다.
- 이메일 형식 검증 테스트를 작성한다.
- 생성 링크 발송 성공/실패 mutation 테스트를 작성한다.
- 참여 링크 발송 성공/실패 mutation 테스트를 작성한다.
- 이메일 인증 대기 화면 전환 테스트를 작성한다.
- 재전송 성공 토스트 테스트를 작성한다.
- `/workspace-access` 초기 페이지 E2E smoke 테스트를 Figma 화면 기준으로 갱신하고 `/` 진입점 이동도 검증한다.
